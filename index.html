1900s Retro Website

school work experience — figma to code

My first ever proper project. I had just started learning HTML and CSS with no prior knowledge, and my school gave me a work experience brief: design and build a website inspired by the 1900s era. I began in Figma, sketching out monochrome layouts, pixel-style typography, and rigid grid structures that mirrored early web design. Translating those Figma mockups into actual HTML and CSS was where I really learned how design tools connect to code. I used table-inspired layouts rebuilt with modern CSS, limited myself to black-and-white with subtle greys, and focused on semantic structure. It was rough, it was challenging, and it taught me more in two weeks than months of theory could have.

Design Process

MY DESIGN APPROACH

When I started, I couldn't code what I imagined. So I learned Figma first — wireframing layouts, experimenting with colour palettes, and understanding spacing before touching a text editor. My 1900s website project began as a Figma board with 12 artboards exploring different monochrome layouts. That process taught me that good UX starts with asking "what does the user expect?" — whether they're browsing a retro site or a modern dashboard. I still start every project in Figma now, even though I can code much faster.

How I Got Here

My Story

I began with absolutely no coding knowledge — I didn't even know what HTML stood for. I started watching YouTube tutorials, breaking things on purpose, and rebuilding them until they worked. My school work experience was the turning point: I had to design a 1900s website in Figma and then actually build it. I failed repeatedly — broken layouts, CSS that wouldn't apply, colours that looked wrong. But each failure taught me something concrete. Now at Uxbridge College, I'm formalising what I taught myself and filling the gaps I didn't know existed.

MY SKILLSET

I don't claim to know everything — I claim to learn fast. Starting from scratch meant I had to build habits around problem-solving rather than memorising syntax. My 1900s project forced me to understand CSS positioning deeply because I couldn't rely on frameworks. Now I'm comfortable with semantic HTML, responsive CSS, basic JavaScript DOM manipulation, and MySQL database design. I write code, break it, fix it, and document what I learned.

MySQL

Learning relational databases at college. Built a student records system with proper primary keys, foreign key constraints, and normalised tables to eliminate redundancy.

ER Modeling

Drawing entity-relationship diagrams before writing any SQL. Planning relationships between students, courses, and enrolments taught me to think structurally.

SQL Queries

Writing SELECT statements with JOINs, GROUP BY, and aggregate functions. Still learning subqueries and optimisation, but comfortable with the fundamentals.

Data Security

Understanding input sanitisation, prepared statements, and basic access control. Learning that security isn't an afterthought — it's part of the design.
